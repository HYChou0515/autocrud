## Overview

The SpecStar Web project has a two-component architecture:

```
generator/templates/base/     ← Source templates (shipped in npm package)
         ↕ sync
app/                          ← Development app (working copy)
```

During development, you edit files in `app/`. When ready to publish the generator, you sync `app/ → generator/templates/base/` to update the templates. When a user runs `npx specstar-web init`, the `templates/base/` files are copied into their new project.

---

## Sync Direction: App → Templates

The sync is **one-way**: `app/` is the source of truth, `generator/templates/base/` is the destination. Never edit template files directly — always edit in `app/` and sync.

```
app/src/specstar/lib/         →  generator/templates/base/src/specstar/lib/
app/src/App.tsx               →  generator/templates/base/src/App.tsx
app/vite.config.ts            →  generator/templates/base/vite.config.ts
app/package.json              →  generator/templates/base/package.json
...                           →  ...
```

## Template vs Generated File Separation

```
app/src/specstar/
├── generated/                  ← EXCLUDED from sync (regenerated by CLI)
│   ├── types.ts                OpenAPI → TypeScript interfaces
│   ├── resources.ts            Resource registry with Zod schemas
│   ├── branding.ts             APP_TITLE + APP_LOGO
│   └── api/                    Axios clients (one per resource)
│
├── lib/                        ← INCLUDED in sync (template code)
│   ├── client.ts               Axios instance config
│   ├── resources.ts            Resource registration logic
│   ├── resourceCustomization.ts  User customization entry point
│   ├── components/             All reusable UI components
│   ├── hooks/                  React hooks
│   ├── types/                  Internal TypeScript types
│   └── utils/                  Error notification, form utils, etc.
│
└── types/
    └── api.ts                  ← INCLUDED in sync

app/public/                     ← INCLUDED in sync (specstar-mark.svg, etc.)

app/src/routes/
├── __root.tsx                  ← INCLUDED in sync
├── index.tsx                   ← INCLUDED in sync *and* regenerated (see below)
├── specstar-admin.tsx          ← INCLUDED in sync
└── specstar-admin/             ← EXCLUDED from sync (generated route pages)
    ├── index.tsx               Generated dashboard
    ├── backup.tsx              Generated backup page
    └── {resource}/             Generated per-resource pages

app/src/routeTree.gen.ts        ← EXCLUDED (TanStack Router auto-generated)
```

**Rule**: If the generator's `generate` command creates or overwrites a file, it's **excluded** from sync. Everything else (the "framework" layer) is **included**.

**The one exception is `src/routes/index.tsx`.** It is synced from `app/` *and* rewritten by `generate` (from `genRootIndex()` in `generator/src/codegen/routes-gen.ts`), because it is both the placeholder a fresh `init` needs and a page the generator regenerates. Editing the landing page therefore means editing **two** places and keeping them identical — the `app/` copy and the `genRootIndex()` template string. Change only one and the page silently reverts on the next `generate`.

## make sync-templates Breakdown

```bash
make sync-templates
```

Executes two steps:

### Step 1: Format App Code

```bash
cd app && make style    # prettier + eslint --fix
```

Ensures consistent formatting before syncing, so templates always have canonical formatting.

### Step 2: rsync

```bash
rsync -av --delete \
  --exclude='node_modules' \
  --exclude='.vite' \
  --exclude='.tanstack' \
  --exclude='dist' \
  --exclude='.env' \
  --exclude='.mantine-version' \
  --exclude='coverage' \
  --exclude='pnpm-lock.yaml' \
  --exclude='src/specstar/generated' \
  --exclude='src/routes/specstar-admin' \
  --exclude='src/routeTree.gen.ts' \
  app/ generator/templates/base/
```

**Flag meanings**:
- `-a` (archive): Preserves permissions, timestamps, symlinks, recursive
- `-v` (verbose): Shows transferred files
- `--delete`: Removes files from `templates/base/` that no longer exist in `app/`

**Excluded directories/files**:

| Exclude | Reason |
|---------|--------|
| `node_modules` | Install artifact |
| `.vite` | Vite cache |
| `.tanstack` | TanStack Router cache |
| `dist` | Build output |
| `.env` | Local environment config |
| `.mantine-version` | Runtime version marker |
| `coverage` | Test coverage reports |
| `pnpm-lock.yaml` | Lock file (regenerated per project) |
| `src/specstar/generated` | Generator output |
| `src/routes/specstar-admin` | Generator output (route pages) |
| `src/routeTree.gen.ts` | TanStack Router auto-generated tree |

## CLI Init Flow: Templates → New App

When a user runs `npx specstar-web init my-app`:

```
1. Copy entire generator/templates/base/ → my-app/
2. Apply Mantine version selection (7 or 8)
3. Optionally include test files (--include-tests)
4. Run pnpm install in the new project
```

After `init`, the user runs `npx specstar-web generate` to populate the `generated/` directory from their backend's OpenAPI spec.

---

## Regeneration Flow: Backend → Generated Code

When running `make regen-app` or `npx specstar-web generate`:

```
1. Delete existing generated files:
   - rm -rf app/src/specstar/generated
   - rm -rf app/src/routes/specstar-admin

2. Fetch OpenAPI spec:
   - GET {backend-url}/openapi.json

3. Parse and generate:
   - types.ts       ← From OpenAPI schemas
   - resources.ts   ← Resource registry with field metadata + Zod schemas
   - api/*.ts        ← One Axios client per resource

4. Generate route pages:
   - specstar-admin/index.tsx      ← Dashboard
   - specstar-admin/backup.tsx     ← Backup/restore page
   - specstar-admin/{resource}/    ← Per-resource CRUD pages
```

**Important**: `resourceCustomization.ts` is in `lib/` (not `generated/`) and is **never overwritten** by the generator. This is the safe place for user customizations.

## Development Workflow

### Daily Development (Editing Components)

```
1. Edit files in app/src/specstar/lib/
2. Test with make dev-app
3. When satisfied, run make sync-templates
4. Commit both app/ and generator/templates/base/ changes
```

### Backend Schema Changed

```
1. make regen-app        (re-generates types, api, routes)
2. git diff              (review changes in generated/)
3. Test with make dev-app
```

### Publishing Generator

```
1. make sync-templates   (ensure templates match app)
2. make publish          (style + sync + build + npm publish)
```

### Important Gotchas

- **Never edit `generator/templates/base/` directly** — changes will be overwritten by next sync
- **Never edit files in `app/src/specstar/generated/`** — overwritten by `generate`
- **`resourceCustomization.ts` is safe** — generator skips it if it already exists
- **`pnpm-lock.yaml` is excluded** from sync — each project generates its own
- **`.env` is excluded** — each deployment has its own environment
